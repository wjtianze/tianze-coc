# tianze-coc

把部落冲突（Clash of Clans）客户端本身改造成可编程的战斗模拟器：注入探针接管引擎，
Python 侧提供 `reset / step` 战斗环境，可离线反复开局、任意换阵型、锁步加速，为训练进攻 AI 做好底层与中间层。

## 🙏 致谢 FirstLight CR —— 没有它就没有这个项目

**这个项目从头到尾都是在 [FirstLight CR](https://github.com/Jaasssoooonnnnn/FirstLight_CR) 的肩膀上做出来的。**

FirstLight CR 是一个皇室战争 AI 研究项目，它证明了一条在当时看来近乎疯狂的路线：
**不截图、不识图，而是把游戏客户端本身变成模拟器**——往原版 APK 里注入原生探针，hook 游戏引擎，
在引擎内部直接执行动作、读取真实的对局状态，再在此基础上做模仿学习和 PPO 自我对弈，最终把模型打上了名人堂。

tianze-coc 几乎照搬了它的全部思路：

- **核心路线**：注入探针 + 引擎内执行动作 + 结构化观测，而不是视觉方案；
- **工程分层**：原生探针 / 引擎传输 / 战斗环境 / 策略与训练，连目录划分都是照着学的；
- **关键设计**：入口指纹校验、锁步推进、与游戏 UI 同一条命令提交路径、JSON 行协议的本地策略服务；
- **研究方法**：录像 → 引擎内重建 → 模仿学习 → 自我对弈的整套训练路线，也是我们为 19 本训练准备沿用的方案；
- **文档风格**：架构说明、兼容数据、验证清单的写法。

FirstLight CR 的作者把探针、APK 构建工具、战斗环境、训练代码、模型和 25 万局录像数据集全部开源出来，
还写了极其坦诚的训练历史（包括"对着被动的 IL 对手刷出 80% 胜率其实是在钻空子"这种踩坑记录）。
这种开放和诚实，是这个项目能在短时间内从零走到真机跑通的根本原因。

**向 FirstLight CR 的作者和所有贡献者致以最诚挚的感谢！** 如果你对游戏 AI 感兴趣，请一定先去看、去 star
[FirstLight CR](https://github.com/Jaasssoooonnnnn/FirstLight_CR)。

| 项目 | 状态 |
| --- | --- |
| 游戏版本 | Atrasis 私服客户端 `com.atrasis.original` 18.647（build `18_647_2`），**2026 年 11 月，18 本时代的最后一个版本** |
| 底层（注入探针） | ✅ 完成，已在 MuMu 12（Android 12，ARM64 转译）真机运行 |
| 中间层（Python 战斗环境） | ✅ 完成，全部进攻动作已在 18 本满级账号上真机验证 |
| 离线开局 / 换阵型 / 断网 | ✅ 完成，真机验证 |
| **AI 模型** | ❌ **没有制作，本版本也不打算制作** |

**关于模型**：训练需要 GPU，而游戏即将进入 19 本时代，单位、建筑和数值都会大改。
在 18 本最后一个版本上训练出来的模型很快就会过时，所以这个版本只做底层和中间层，
**等 19 本版本出来之后，再在新版本上重新定位偏移并训练模型**。
仓库里的 `tianze_coc/training/loop.py` 只是一个用来证明"环境 → 策略 → 奖励 → 更新"链路可以跑通的占位策略，不是模型。

## 它能做什么

```
Python 中间层 (tianze_coc)              模拟器内 (Atrasis 私服客户端)
┌──────────────────────────────┐  adb   ┌─────────────────────────────────────────────┐
│ TianzeBattleEnv              │forward │ libg.so ──DT_NEEDED──> libtianze_probe.so    │
│  reset / step / 规则校验      │◄──────►│  · hook GameMode::updateSubTick：锁步/加速     │
│ OfflineStarter（离线开局）     │ :27650 │  · 主线程构造并提交命令（与游戏 UI 同一路径）     │
│ home_payload（换阵型）        │        │  · 录制/重放服务器消息、离线时拦截外发消息         │
│ 单位目录 / 防守目录            │        │  · 读取对局状态、对象坐标血量、兵力、星数          │
└──────────────────────────────┘        └─────────────────────────────────────────────┘
```

**全部进攻动作（均在真机验证）**

| 动作 | 说明 |
| --- | --- |
| `troop` / `siege` / `spell` / `hero` | 兵种、攻城机器、法术、英雄（战宠随英雄出场） |
| `ability` | 英雄技能 |
| `hero_mode` | 大守护者地面/空中模式切换（部署前） |
| `cc` | 部落援军（传送门，援军兵种全部出场） |
| `cc_siege` / `cc_spell` | 部落城堡里的攻城机器、援军法术（自动按等级匹配） |
| `recalled` | 回溯法术收回后重新部署 |

规则与游戏一致，在环境层强制：只能使用部落战/排位战可携带的单位（限时兵种/法术禁用）；
可携带多台攻城机器但一局只能部署一台；开战后只能切换要部署的攻城机器和大守护者模式。

**观测**：tick、摧毁率、星数、大本营是否被摧毁、战斗结束；剩余兵力/法术/攻城机器/部落援军（含等级）；
所有对象的坐标、血量、最大血量、阵营。

**离线开局**：正常打一局时自动录下服务器下发的村庄数据，之后在本地重放即可反复开局（约 1 秒/局），
模拟是确定性的；可以把录制里的对手村庄换成任意阵型；离线时拦截外发消息，不向服务器提交结果。

**单位规则表**由脚本从 APK 的 CSV 自动生成并经人工审核：
[进攻方 docs/units.md](docs/units.md)、[防守方 docs/defenses.md](docs/defenses.md)。

## 目录

| 路径 | 作用 |
| --- | --- |
| `tools/re/` | 静态分析工具（函数边界、交叉引用、命令工厂/消息分发解析）与 **偏移自动定位** `find_offsets.py` |
| `probe/src/` | C++ 探针：inline hook、命令注入、锁步、快照、消息录制/重放、命令侦听、TCP 服务 |
| `probe/generated/offsets.h` | 自动生成的地址、结构偏移与入口指纹 |
| `tianze_coc/` | Python 中间层：战斗环境、协议客户端、离线开局、换阵型、单位目录、APK 注入与安装 |
| `tools/calibrate.py` | 对象字段校准（坐标/血量/阵营） |
| `tools/live_action_test.py` | 真机动作测试 |
| `docs/architecture.md` | 逆向结论、每个偏移的证据、协议、真机联调记录 |

## 快速开始

见 [docs/getting_started.md](docs/getting_started.md)。不连模拟器也可以先跑测试（使用模拟探针）：

```bash
python -m unittest discover -s tests -t .
```

仓库**不包含**游戏 APK，也不包含任何录制数据（录制里有账号信息）。需要自行准备 Atrasis 18.647 客户端，
登录后正常打一局，用 `offline_session.save_records()` 保存自己的录制。
